# 폴더 분리 기록

## 이동

- `baemin-flutter` → `apps/mobile`
- `baemin-calendar-mock` → `apps/web`
- 초기 루트 웹 3개 파일·이미지 → `apps/legacy-web`
- Flutter 내부 단일 lib 파일들을 `app`, `core`, `features`, `shared`로 분류. 초기화는 `main.dart`, 테마는 `app/app.dart`, 최상위 탭은 `app/home_shell.dart`.
- Flutter 폴더에 있던 분석 브리지·서버 토큰과 웹 서버의 분석 함수를 `services/nutrition-api`로 분리. 웹 서버가 가진 분석 로직과 API 서버가 같은 모듈을 사용.
- Python 테스트를 서버 모듈 옆으로 이동하고 테스트 사진을 서비스 자체 fixture로 보관. API 서비스는 웹 폴더 없이 테스트 가능.
- README·실기기 안내·카탈로그 내보내기·캡처 도구의 상대 경로 갱신. 기존 비밀키는 복사하지 않고 이동했으며 Git에서 제외.

## 검증 중 발견한 기존 날짜 의존성

기존 예시 쿠폰은 10월의 고정 유효기간을 가졌고 테스트는 현재 날짜를 사용해 11월에 실패했다. 앱 데이터·쿠폰 정책은 변경하지 않았다. 모바일 테스트용 seed에서만 쿠폰 발급/만료일을 실행일 기준으로 잡고, 혜택 테스트는 다음 달의 혜택 날짜를 고른다. 웹 쿠폰 테스트는 주문일과 같은 날짜의 쿠폰을 생성한다. 만료 쿠폰을 검증하는 별도 테스트는 그대로 유지한다.

## 검증 결과

- Flutter 테스트 69개, 웹 Node 테스트 46개, Python 분석/API 테스트 10개 통과.
- `make analyze` 정적 분석 오류 없음. 한글 작업 경로에서 Flutter LSP 분석기가 실패해 `tools/analyze.sh`에서 Dart 분석기를 직접 호출한다.
- Flutter 웹 release 빌드 성공.
- 임시 포트에서 독립 분석 API 실행, 설정 조회, 웹 HTML·이미지 제공, 두 진입점의 예시 분석 응답을 HTTP로 확인. 외부 유료 모델 호출은 수행하지 않았다.
- 카탈로그/번들 이미지·폰트·플랫폼 소스는 원본 해시와 일치한다. 코드 이동·문서·경로·테스트 fixture 외 기능 데이터 변경은 없다.
- 서버 `.env`는 권한 0600으로 유지되며 Git 제외 확인. 업로드 대상에서 실제 토큰·주요 비밀키 패턴이 검출되지 않았다.
- 이동한 앱 경로에서 iOS release 서명 제외 빌드 성공(52.6MB). 폴더 분리 검증을 위한 컴파일이며 실기기 재설치·화면 동작을 새로 확인한 것은 아니다.
