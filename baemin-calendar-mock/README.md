# 배민 주문 캘린더 · 실행 가능한 준비 버전

현재 미리보기: **http://localhost:4180/**

기존 `localhost:4173` 한끼록과 별도의 폴더·저장소·서버로 실행한다. 실제 배민 주문내역에서 확인한 카드 구조와 하단 탐색을 참고해 만든 프로토타입이며, 실제 주문·개인정보를 가져오지 않는다.

## 실행

Python 3.11 이상, 브라우저가 필요하다. 기본 실행에는 pip/npm 설치가 필요 없다.

```sh
cd '/Users/jongseok/Documents/sejong_univ/26-2/아람제x배민/baemin-calendar-mock'
python3 server.py --port 4180
```

이 폴더를 일반 정적 서버로만 열면 사진 분석 API는 동작하지 않는다. `server.py`로 실행한다.

## 바로 테스트할 수 있는 것

1. **홈에서 주문**: 카테고리·가게·메뉴 선택 → 수량 → 장바구니 → 주문하기. 현재 한국 날짜의 캘린더에 반영한다. 직접 생성 버튼은 제거했다.
2. **다음 단계**: 접수 대기 → 조리 중 → 배달 중 → 배달 완료. 데스크톱 제어판 또는 주문상세에서 조작한다. 접수 대기에서는 가상 취소 가능.
3. **식사로 기록**: 완료 주문에서 실제 먹은 날짜·양을 선택한다. 배민 제공 데이터 구조를 재현한 시연값을 사용한다.
4. **캘린더 날짜에서 음식 촬영·등록**: 날짜 선택 → 촬영·등록 → 파일 선택 또는 모바일 촬영 → 데모/실제 분석 선택 → 음식명·칼로리·탄단지 확인·수정 → 캘린더 저장.
5. **찜·마이배민**: 가게 찜 동기화, 기록한 식사·열량 합계, 가상 리뷰관리.
6. **장보기·쇼핑**: 4개 매장·20개 상품의 검색/분류/담기/수량 변경/주문/배송상태를 지원한다. 구매내역은 별도 서비스 탭에서 조회하며 식사 기록에 자동 합산하지 않는다.
7. **월간·주간·필터**: 9월과 10월 합성 데이터, 같은 날짜 다중 주문, 취소·사진 기록 분리.

배달 완료를 곧바로 식사 완료로 간주하지 않는다. 주문일과 먹은 날을 분리하며, 동일 주문의 식사 기록은 중복 추가하지 않는다. 저장은 브라우저 localStorage의 `baemin-order-calendar-mock-v1`에 한 번에 수행한다. 원래 `hankkirok-meals-v1`은 건드리지 않는다.

## Hugging Face 연결

기본값은 **분석 데모**다. 선택한 예시 음식의 고정값을 반환하며 사진을 판독하지 않는다. 화면과 저장 데이터에도 데모 출처를 표시한다.

실제 사진 분석은 서버 환경변수 `HF_TOKEN`과 `HF_MODEL_ID`를 사용한다. 서버를 종료한 뒤 환경변수를 설정하고 다시 실행한다. 토큰을 채팅·프런트엔드·공개 파일에 넣지 않는다. 아래는 zsh에서 입력을 숨기는 예다.

```sh
read -s 'HF_TOKEN?Hugging Face token: '
export HF_TOKEN
export HF_MODEL_ID='Qwen/Qwen2.5-VL-7B-Instruct:featherless-ai'
python3 server.py --port 4180
```

`.env.example`은 변수 이름 참고용이며 자동 로드하지 않는다. 상위 폴더의 일반 HTTP 서버는 파일을 그대로 제공할 수 있으므로 실제 토큰을 담은 `.env`를 프로젝트 폴더에 저장하지 않는다.

Hugging Face의 Inference Providers 권한이 있는 토큰, 모델·제공자 접근 권한 및 추론 사용 한도가 필요하다. 사용량에 따른 비용이 생길 수 있다. 화면에서 **Hugging Face · 실제 사진 분석**을 고르고 사진 전송에 동의하면 요청한다. 키가 없거나 모델 응답이 실패하면 오류를 표시하며 데모값으로 바꾸지 않는다.

- 호출: `POST https://router.huggingface.co/v1/chat/completions`.
- 입력: 재인코딩한 음식 이미지 + 음식·영양 추정 JSON 요청.
- 출력: 음식명, 추정 재료, 사진 전체 분량의 열량(kcal)·탄수화물/단백질/지방(g).
- 저장: 모델 ID·출처·확인한 영양값을 보존한다.

**실제 HF 요청은 아직 미검증**이다. 현재 환경에 키가 없어 HTTP 전송·응답 처리 어댑터는 가짜 모델 응답으로 검증했다. 모델 제공자의 실제 이미지 입력 지원, 계정 접근·사용량·한국 음식 정확도는 연결 후 확인해야 한다. 사진 한 장에서 분량·조리 재료를 정확히 측정했다고 표현하지 않는다.

## 배민 공급 데이터 연결

현재의 배달 영양값은 가상 카탈로그다. 실제 배민의 공개 영양 API를 발견하거나 연결한 것이 아니다. 미래의 배민/가맹점 제공 데이터를 받을 계약과 정규화 함수는 [연동 설계](INTEGRATION.md), [supplier.mjs](supplier.mjs)에 준비했다.

## 검증

```sh
node --test domain.test.mjs commerce.test.mjs insights.test.mjs calendar.test.mjs
python3 -m unittest -v test_server.py
```

자동 테스트 26개 통과. 홈 메뉴 선택→수량 2개→장바구니→주문→배달 완료, 장보기 상품 필터→우유/계란 담기→배송 완료→별도 구매내역, 캘린더 날짜→촬영 등록 진입을 브라우저에서 확인했다. 이전 검증에서는 브라우저에서 주문 생성→조리→배달→완료→절반 섭취 저장, 사진 선택→데모 결과 수정→저장, 새로고침 복원, 주간 전환·마이 요약, 모바일 분기 레이아웃을 확인했다.

## 남은 실제 연동·제품 범위

- HF 실호출과 실제 음식 사진 검증, 음식별 정답·분량이 있는 평가셋 준비.
- 배민 측 데이터 제공 계약·인증·메뉴별 영양 데이터 품질과 수량/옵션 대응.
- 일반 배달·픽업 선택과 장보기의 로컬 주문 경로를 지원한다. 함께주문·부분취소·쿠폰 조합·실제 지도·실제 결제는 미구현.
- 휴대전화의 실제 카메라 실행은 미검증. `capture="environment"` 파일 입력을 제공하지만 HTTPS/localhost 같은 안전한 컨텍스트와 기기 브라우저 지원이 필요하다. Mac의 localhost URL이 휴대전화의 localhost로 연결되는 것은 아니다.
- 기록은 단일 브라우저에만 저장한다. 다중 기기 공유·로그인·서버 DB·동기화는 후속 범위다.
- 섭취 기록 편집·삭제와 세부 영양소(나트륨·당류 등)는 후속 확장이다. 현 버전은 확인 저장과 시연 전체 초기화를 지원한다.

초기화는 시연 저장 키만 복원한다. 시연 중 추가한 테스트 주문과 사진 기록은 초기화할 때 사라진다.

## 배민 UI 유사도 개선 (2026-10-26)

실기 캡처 P01·P02·P06·P09를 기준으로 상단 제목/서비스 탭, 검색·조회기간·상태 필터, 둥근 하단 메뉴바, 주문 카드·금액·리뷰·재주문 버튼, 찜 목록, 마이배민 프로필·지갑·찜 미리보기의 배치를 조정했다. 한 끼 캘린더·촬영·영양 기록은 개선안으로 추가했다.

프로필 PNG는 캡처를 입력으로 배경을 제거·재구성했고, 메뉴 사진은 캡처 스타일을 참고한 새 시연 이미지다. 작은 메뉴 아이콘은 SVG로 재현했다. [에셋 출처와 전체 프롬프트](assets/README.md).

검색은 가게/메뉴명으로 캘린더 표시를 좁히며 조회 기간은 월 선택, 주문 상태는 완료/취소/배달/사진 기록을 지원한다. 검색 중에는 검색 대상과 혼동될 수 있는 하루 전체 영양 합계를 숨긴다. 주소별 조회 및 실제 계정 메뉴는 구현 범위에 포함하지 않는다. 기존 주문·식사 저장 상태는 유지한다.

## 홈·장보기 확장과 댓글 반영

- 홈: 관찰한 R02·R12를 기준으로 주소·검색창·서비스 탭·음식 카테고리·매장 바로가기·추천 메뉴·가게 메뉴 목록을 구성했다. 음식 메뉴는 현재 27개다.
- 장보기·쇼핑: 이전 실기 조사에서 확인한 검색·매장 아이콘·프로모션·주변 가게 구성을 참고했다. 이번 미러링에서는 화면 읽기는 됐지만 입력이 실패해 장보기 세부 화면을 새로 탐색하지 못했다. 세부 상품·장바구니는 시연 설계이며 현재 배민과 완전히 동일하다고 검증한 것은 아니다.
- 직접 가상 주문 생성 버튼, 캘린더 상단 음식기록 버튼, 내역 하단 주문/촬영 버튼, 우측 제어판의 주문/촬영 버튼을 제거했다. 새 주문은 메뉴·상품 탐색 후 장바구니 결제로만 생성한다. 재주문 버튼도 홈 가게 메뉴로 이동한다.
- 사진 등록은 캘린더 날짜 선택 후 시트에서만 진입한다. 마이배민의 기록 진입은 캘린더로 이동한다.
- 예전 QA의 저화질 합성 비빔밥 기록은 해당 데모 이름/출처/작은 이미지 조건에서만 고해상도 시연 사진으로 표시한다. 사용자가 추가한 일반 사진이나 저장된 원본 이미지는 덮어쓰지 않는다.
- 주문 시각과 카드 날짜는 한국 시간으로 표시한다. 장바구니는 별도 `baemin-commerce-cart-v1`에 저장한다.

## 식습관 리포트와 다음 한 끼 제안

직접 열기: **http://localhost:4180/?view=report** 또는 마이배민 → 나의 식습관 리포트.

Figma 온라인 24페이지(노드 231:1151)를 브라우저에서 직접 확인해 주·월/영양 요약/기록 이해라는 방향을 참고했다. 건강 진단이나 실제 서비스 화면 전체를 복제하는 작업은 아니다.

- 완료한 배달, 확인한 식사, 기록한 날을 분리해 계산한다. 빈 날은 미기록으로 남긴다. 취소/진행 중/장보기 구매는 식사 합계에서 제외한다.
- 배달 빈도·메뉴 반복과 제공된 메뉴 구성을 근거로 집밥 재료/포케·샐러드 탐색을 제안한다. 나트륨·당류처럼 없는 데이터는 채우지 않는다.
- PB 재료 볶음밥과 동네마트 샌드위치 레시피 → 재료 장바구니. PB 상품 2개와 동네마트 재료를 추가했다. 가격은 포장 단위이며 한 끼 원가가 아니다.
- 이미 발급된 **시연 쿠폰 3개**를 둔다. 확인/미확인·기간·최소금액·대상 가게/메뉴·PB 포함 조건·사용 여부를 확인한다. 주문에 쿠폰을 쓰면 주문 금액과 사용 상태를 함께 저장하고, 전체 취소 시 기간을 연장하지 않고 복원한다.
- 쿠폰함·혜택모아보기·리포트에서 혜택을 확인할 수 있다. 실제 배민 계정의 쿠폰을 조회하거나 새로 발급하는 API는 연결하지 않았다.
- 우측 리포트 미리보기의 ‘배달이 잦은 주 예시’는 파생 표시만 변경하며 기존 주문·식사 데이터에 추가하지 않는다.
- 프로필 이름은 ‘민수’, 이름 옆 편집 아이콘은 제거. 고객센터/설정 원본 아이콘의 경계 처리를 개선하고 이미지 주소 버전을 갱신했다.

## 전체 화면 주문과 제어판 제거

메뉴/상품 상세·장바구니·주문상세를 휴대폰 전체 화면 전환으로 바꾸고, 상단 뒤로가기·브라우저 이력을 연결했다. 시연 제어판은 DOM/이벤트에서 제거했다. 진행 단계는 주문상세에서 조작할 수 있다. CU·GS25·전체보기 캡처 좌표를 교정했고 홈 배너는 리포트로 연결한다.

현재 목업은 웹으로 유지했다. [구현 범위·Flutter/네이티브 비용 추정과 검증 상태](PLATFORM_OPTIONS.md). 이번 변경 이후 브라우저 제어가 설정에서 비활성화되어 최종 렌더/클릭 확인은 하지 못했다.

## 리포트 위치

식습관 리포트는 주문내역의 배달·픽업 캘린더 아래에서 연다. 리포트에서도 하단 주문내역 탭이 선택되며, 상단 뒤로가기는 주문내역으로 돌아간다. 마이배민의 리포트 카드와 홈의 리포트 연결은 제거했고 홈 배너는 장보기로 연결한다.

## 사진 캘린더와 날짜별 혜택 (2026-10-26)

- 날짜 칸: 음식 사진 배경·먹은 날짜 기준의 확인한 식사 kcal 합계·식사 개수 점. 미확인 주문은 사진 위에 ‘식사 확인’을 표시한다. 빈 날은 0kcal로 표시하지 않는다.
- 날짜 상세: 음식별 사진/이름/칼로리, 미확인 주문의 섭취 확인, 촬영 등록, 해당 날짜의 혜택 조건을 함께 표시한다.
- 시연 일정(매월): 18·19·26·28일 음식 주문 10,000원 이상 완료 시 500P, 20·25·30일 픽업 9,000원 이상 완료 시 1,000P, 22·23·29일 당일 받는 B마트 3,000원 쿠폰(9,000원 이상 구매).
- 포인트는 주문일 기준이며 주문 완료 후 하루 혜택별 1회 적립한다. 취소·진행 중·장보기 주문은 음식 주문 포인트 대상이 아니다. 마이배민에 누적 시연 포인트를 표시하고 새로고침 후 유지한다. 포인트 사용·실계정 연동은 범위 밖이다.
- 캘린더 쿠폰은 해당 날짜에만 한 번 받고 당일 사용한다. 기존 쿠폰 검증/장바구니/사용 처리와 연결된다. 실제 배민 프로모션을 재현한 약관이나 확정된 금액이 아니라 UX 시연 규칙이다.
- 혜택 3종 아이콘은 사용자가 첨부한 참고 이미지에서 직접 절단해 가장자리 흰 배경만 제거했다. 매장 목록은 기존 원본 캡처 로고를 사용한다.
- 검증: JS 27개 + Python 5개 = 자동 32개 통과. 브라우저에서 날짜별 음식/칼로리, 미래 쿠폰 비활성화, 픽업 가게 이동, 장바구니 500P 안내 → 주문 완료 적립 → 마이배민 500P → 새로고침 복원을 확인했다. 주문 생성 검증은 `127.0.0.1` 저장소에서 수행해 `localhost`의 사용자 시연 주문과 분리했다.

## 실제 앱 주문상세 구성과 식습관 요약 보완 (2026-10-26)

- 실제 미러링에서 확보했던 배달 완료(P07), 픽업 완료(P05), 취소(P14) 캡처를 기준으로 주문상세를 재구성했다. 현재 미러링은 연결이 끊겨 새 런타임 화면은 확인하지 못했고, 저장된 캡처에서 확인한 범위와 새 제안 기능을 구분한다.
- 상단 가운데 제목/장바구니, 테두리 상태 카드/가게 행/찜, 주문 메뉴·결제 정보·배달/주문 정보 탭, 메뉴별 가격·수량 카드와 재주문 버튼, 결제 내역과 받는 정보를 표시한다. 탭은 해당 섹션으로 이동한다. 메뉴 옵션·실제 주소/결제수단은 확보하거나 연동하지 않았다. 영양/식사 기록은 제안 기능으로 아래에 배치했다.
- 캘린더 음식 스프라이트는 원본 타일을 정사각형으로 유지한 채 칸에 맞춰 잘라 표시한다. 혜택 숫자는 키우고 캘린더 아래 안내 행을 제거했다.
- 날짜 상세에서 지난 혜택을 숨기고, 돌아가기 버튼을 제거했다. 촬영 등록은 주 색상의 원형 카메라 버튼으로 유지한다. 상단 X로 닫는다.
- 리포트 진입 카드/상세 첫 요약은 기록 수 대신 확인한 식사의 배달 비중·한 끼 평균 열량, 완료한 배달의 주요 메뉴 분류 비중을 보여준다. 탄단지 구성은 기록한 g값을 4/4/9 kcal로 환산한 에너지 비율이며 합계 100%가 되도록 반올림한다. 알 수 없는 값은 ‘—’로 표시하고 건강 점수나 임상 판정을 만들지 않는다.

최신 검증: 자동 34개(JS 29 + Python 5) 통과. 브라우저에서 배달 완료/취소 주문상세, 결제 정보 이동·환불 금액, 종료 혜택 비노출, 돌아가기 버튼 제거, 원형 촬영 버튼의 중심 오차 0.01px 미만 및 등록 진입, 음식 배경의 가로·세로 비율 1:1, 식습관 요약과 리포트 진입을 확인했다.

## 혜택 공개 모션·가독성·글래스 탐색 (2026-10-26)

- 캘린더의 포인트·쿠폰·픽업 날짜는 혜택 공개 화면을 연다. 음식이 있는 날에는 음식 칸과 혜택 배지를 별도의 버튼으로 분리했다. 음식 칸은 일별 식사 목록, 배지는 혜택 공개로 연결한다.
- 혜택 공개: 원본 캡처 아이콘의 팝·회전·확산 링·색종이, 순서대로 나타나는 조건/CTA. 0.8초 내외의 고정 혜택 공개 연출이며 무작위 추첨이나 확정 지급을 표시하지 않는다. ‘주문하러 가기’는 음식배달 홈, B마트, 픽업 홈으로 연결된다. 예정 날짜에는 미래 조건을 안내하고 쿠폰을 미리 발급하거나 날짜를 바꿔 주문하지 않는다. 실제 적립/쿠폰 처리는 기존 완료·최소금액·날짜 규칙을 유지한다.
- 종료된 혜택은 캘린더에서도 숨긴다. 쿠폰 날짜에는 아이콘만 보이고 금액 문구를 표시하지 않는다. 구체적인 사용 조건은 혜택을 열어 확인한다.
- 작은 보조 글씨는 주로 11~12px로 높였고 하단 메뉴는 11px, 도움말/범위 설명은 10~11px로 조정했다. 캘린더 포인트는 10~11px다.
- 하단 메뉴는 반투명 다층 배경·24px 배경 흐림·채도·가장자리 반사·움직이는 선택 캡슐로 글래스 느낌을 적용했다. CSS 기반의 시각 효과다. 배경 필터 미지원 시 불투명 배경을 사용하며, 동작 줄이기 설정에서는 축하 모션과 선택 캡슐 이동 애니메이션을 끈다.
- 장보기의 큰 노란 이모지 배너를 제거하고 매장 로고 아래 쿠폰 배너로 정리했다. 현재 아이폰 사용 중으로 미러링이 연결되지 않아 새 실기 화면은 확인하지 못했다. 앞선 실기 관찰 기록과 [공식 소개 이미지](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource221/v4/66/2d/d4/662dd491-d72b-6c86-99ac-04e0864501b8/6.png/600x1300bb.webp)를 브라우저에서 확인해 매장→쿠폰 순서와 색상/구성을 참고했다. 공식 이미지의 ‘10% 무제한’ 문구는 현재 시연 쿠폰 규칙과 달라 사용하지 않았다.
- 혜택을 열기만 해서는 저장 상태를 변경하지 않는다. 미래·이미 받은 혜택을 다시 받은 것처럼 표시하지 않는 경계를 자동 검증에 추가했다.
- 최신 자동 검증 36개(JS 31 + Python 5) 통과. 브라우저에서 공개 모션, 주문하러 가기 3개 목적지, 쿠폰 금액 비노출, 종료 아이콘 제거, 매장 로고와 글래스 필터 적용을 확인했다.

## 캘린더와 리포트의 월·주 통합 (2026-10-26)

캘린더에서 선택한 달/주를 요약 카드와 상세 리포트가 함께 집계한다. 주간은 일요일~토요일, 월간은 선택 월의 1일~말일이다. 상세 리포트에서 기간을 바꾸면 캘린더에도 같은 기간이 반영된다. 배달 빈도 규칙은 기간 길이에 맞춰 7일당 4회로 환산한다.

화면의 시연·가상 주문/결제·연결 여부 안내를 제거했다. 사진 등록의 기본 방식은 ‘음식 선택해서 등록’으로 표시해 실제 AI 호출과 혼동하지 않게 했다. 저장된 주문/식사 데이터, 출처·쿠폰 조건·포인트 처리 및 연동 한계는 내부 데이터와 문서에 유지한다. 실제 주문/결제 연동을 추가한 변경이 아니다.

빈 식사 날짜의 ‘— kcal’ 숫자 요약을 없애고 첫 식사 등록 화면을 사용한다. 요약 카드 탄단지 비율을 제거했다.

검증: 자동 39개(JS 34 + Python 5) 통과. 브라우저에서 10월 월간 평균 527kcal → 10.25~31 주간 480kcal → 10.18~24 주간 620kcal로 집계가 바뀌는 것을 별도 127.0.0.1 데이터로 확인했다. 상세 리포트의 9월 선택이 캘린더에도 반영되는 것, 후킹 버튼의 집밥 추천 이동, 빈 날짜 숫자 미노출, 주요 탭·쿠폰·혜택의 시연 문구 부재를 확인했다.

## 식사 패턴 기반 추천과 일별 요약

- 할인 중심 배너를 선택 기간의 배달 비중·메뉴 집중도·메뉴 다양성에 따른 다음 한 끼 카드로 바꿨다. 집밥 레시피 또는 포케·샐러드의 기존 메뉴 상세로 연결한다. 충분한 기록이 없으면 건강 상태를 판정하지 않는다. 쿠폰은 해당 추천에 적용 가능한 경우만 보조 표시한다.
- 일별 총 열량을 큰 숫자·식사 수·음식 사진이 있는 카드로 강조했다. 클릭하면 날짜의 음식별 기록을 확인한다.
- 장바구니 PNG의 원본 숫자 배지가 가린 테두리를 복원해 흰 원처럼 보이던 자국을 제거했다. 아이콘 캐시 버전을 갱신했다.
- 검증: 자동 41개(JS 36 + Python 5) 통과. 브라우저에서 집밥 추천 카드의 레시피 진입과 일별 열량 카드의 음식 기록 진입을 확인했다.

## 추천 카드 여러 버전과 재료 이미지 비율

- 리포트에 따른 첫 추천을 유지하고 총 4개의 서로 다른 메뉴·레시피를 좌우 스와이프/화살표로 탐색한다. 집밥 볶음밥·포케·샌드위치·두부 덮밥 등 기존 목적지와 연결하며 보유 쿠폰 적용 여부를 카드별로 검사한다. 월·주 선택 변경 시 해당 기간에 맞춰 첫 추천을 다시 고른다.
- 재료 목록의 모든 span에 적용되던 flex 확장이 사진까지 늘리던 문제를 수정했다. 사진은 56×56 정사각형으로 고정하고 설명만 남은 공간을 사용한다.
- 이번 검증: JS 자동 37개 통과, 구문 검사·HTTP 파일 제공 확인. Work 설정에서 로컬 브라우저 사용이 비활성화되어 이번 화면의 렌더링·실제 스와이프는 확인하지 못했다.

## 식사 기록에 근거한 개인 맞춤 제안

고정 4개 카드를 채우던 방식은 제거했다. 선택 기간의 배달 식사 비중, 반복 주문 메뉴, 직접 기록한 식사, 알려진 메뉴 분류에 맞는 제안만 표시한다. 각 카드에서 ‘내 식사 기록’의 구체적인 수치·메뉴 → 추천 이유 → 메뉴/레시피/기록 진입을 구분한다. 같은 기간의 주문 메뉴를 확인해 다른 메뉴를 우선 선택하고, 이미 먹은 메뉴를 처음 제안하는 것처럼 표현하지 않는다. 직접 기록이 있다는 사실을 집에서 조리했다는 뜻으로 해석하지 않는다.

상세 리포트의 이유와 메뉴/레시피 목록도 같은 추천 결과를 사용한다. 기록이 적으면 패턴을 단정하지 않고 식사 기록으로 연결한다. 월간·주간에 따라 제안 수와 내용이 달라진다. 기록량·배달 이용 자체에 건강 점수를 부여하지 않는다.

이번 검증: JS 38개 통과. 상세 리포트의 일반 기록/빈 기간 HTML 출력, 구문 검사와 HTTP 제공 확인. 로컬 브라우저 사용이 Work 설정에서 비활성화되어 화면 렌더링은 확인하지 못했다.

## 리포트 혜택·레시피 구성 정리

- 상단 쿠폰 후킹은 추천 레시피/메뉴에 지금 적용 가능한 단일 쿠폰의 할인액을 표시하고 해당 제안으로 이동한다. 중복 쿠폰 금액을 합산하지 않으며 적용할 추천이 없으면 쿠폰함 탐색으로 연결한다. 유효 쿠폰이 없으면 후킹/목록을 숨긴다.
- 하단 쿠폰 영역은 유효한 보유 쿠폰별 금액·조건·유효기간과 사용처 탐색을 제공한다. 리포트는 흰색·검정·민트 톤으로 통일하고 채소 메뉴 구성 수치는 검정으로 표시한다.
- 별도 레시피 소개 카드/열기 버튼 대신 레시피 본문을 리포트에 배치한다. 본문 안에 재료 상품 카드(1인분 사용량/판매 단위/가격/상품 상세), 준비 재료, 5단계 조리법, 팁, 포장 단위 구매 합계·보유 쿠폰·재료 한 번에 담기를 제공한다. 추천 카드에서 열 때도 같은 본문을 사용한다.
- 이번 검증: 기존 JS 38개 통과. 별도 직접 출력 검사에서 유효/없음/만료/사용 쿠폰의 후킹 노출, 재료 카드와 조리 단계, 레시피 구매 합계(6,960원·9,940원)를 확인했다. Work의 로컬 브라우저 사용 비활성화로 화면 렌더링·실제 클릭은 확인하지 못했다.

## 캘린더 정리·클럽 상세 리포트·초기 맞춤 제안

- 음식 사진 칸 위의 작은 혜택 배지를 제거했다. 혜택 전용 날짜의 아이콘과 포인트는 유지하고 픽업 문구는 `+1,000P`만 남겼다. 날짜 상세의 혜택 조회/포인트 처리 규칙은 유지한다.
- 식사 요약과 맞춤 제안은 비회원도 볼 수 있다. 상세 리포트 버튼과 직접 report 경로는 `hasClubMembership(state)`로 로컬 회원 여부를 확인한다. 기존 저장 데이터에 회원 정보가 없으면 비회원으로 취급한다. 안내에서 ‘배민클럽 시작하고 자세히 보기’를 누르면 로컬 `membership.baeminClub=true`를 저장하고 상세로 진입한다. 실제 배민 가입·결제·계정 인증을 연결한 것이 아니며 운영 서비스에서는 서버에서 회원 자격을 검증해야 한다.
- 2일 이상 기록 조건으로 추천을 막던 처리를 제거했다. 한 날짜에 모인 식사도 배달/직접 기록 비중과 실제 주문 메뉴를 활용해 제안을 먼저 제공한다. 장기 반복 패턴 확인은 보조 문구로 표시한다. 식사와 완료 주문이 모두 없을 때만 기록 진입을 제공한다.
- 이번 검증: JS 40개 통과. 하루 4끼(배달 3끼)의 추천 노출, 신규·기존·회원 상태와 저장 복원, 잘못된 회원 플래그 거부를 확인했다. 브라우저 사용 비활성화로 실제 화면은 확인하지 못했다.

## 주재료를 바꾸는 추천·이미지 비율·메뉴 쿠폰

- 초기 패턴 보조 안내 문구를 제거했다. 추천 근거에는 주문/식사 기록을 구분한 큰 횟수·비율과 정확한 분모를 표시한다.
- 채소 비빔밥·두부 덮밥·된장찌개처럼 지정 메뉴가 2회 이상·배달 주문의 40% 이상 반복되면 연어 또는 돼지고기를 주재료로 하는 메뉴를 제안한다. 메뉴 이름에서 실제 채소 섭취량이나 단백질 부족을 추론하지 않는다. 집밥 전환 자체를 건강 개선의 근거로 사용하지 않는다. 그 외 집밥 제안은 재료 비율·양념량을 직접 고르는 조리 구성에 초점을 둔다.
- 가게 대표 이미지와 메뉴 상세의 음식 스프라이트를 정사각형으로 유지하고 가로 창 안에서 중앙을 크롭한다. 실제 img는 object-fit:cover를 사용한다. 화면 렌더링은 아직 확인하지 못했다.
- 메뉴 상세의 보유 쿠폰을 흰 티켓·민트 할인액·최소금액·유효기간·적용/적용 중 상태로 표시한다. 해당 메뉴에 적용 가능한 보유 쿠폰 중 선택한 쿠폰/최대 할인 쿠폰을 보여주며 새로 발급하지 않는다. 선택은 장바구니로 이어지고 결제 시 기존 조건을 다시 검증한다.
- PB 한 끼 채소를 ‘PB 볶음밥용 다짐 채소’로 바꾸고 전용 생성 사진을 사용한다. 가격·영양값은 기존 로컬 fixture를 유지한다. 원래 상품/계정 데이터 연동을 뜻하지 않는다.
- 검증: JS 41 + Python 5 = 46개 통과. 리포트·레시피 출력과 신규 이미지 HTTP 제공 확인. 브라우저 사용 비활성화로 실제 화면/클릭은 미검증.

## 영양소와 균형 중심으로 추천 기준 교체

이전의 배달 비중·메뉴명·주재료 반복을 근거로 한 추천은 `mealSuggestions`에서 제거했다. 현재 기준은 확인한 식사에 저장된 탄수화물·단백질·지방 g을 4/4/9kcal로 환산한 에너지 구성이다. 표시·비교는 소수 첫째 자리까지 한다.

- 참고: 보건복지부·한국영양학회의 [2025 한국인 영양소 섭취기준](https://www.kns.or.kr/fileroom/fileroom_view.asp?BoardID=Kdr&idx=168), 일반 성인 탄수화물 50~65%, 단백질 10~20%, 지방 15~30%. 개인 연령·질환별 목표를 설정한 서비스가 아니며 선택 기간에 기록한 식사의 구성을 비교한다. 하루 필요열량·영양 결핍을 판정하지 않는다.
- 범위 안이면 탄단지 구성을 유지하는 방향으로 안내한다. 범위 밖이면 해당 영양소 비중과 일반 참고 범위를 보여주고, 주식·단백질 반찬·채소를 함께 구성하는 구체적인 방향을 안내한다. 영양정보가 없으면 메뉴명으로 영양 상태를 추정하지 않는다.
- 후보 메뉴의 카탈로그 영양값을 직접 비교한다. 후보 자체의 에너지 구성이 참고 범위 안에 있고, 기록 합계에 다음 한 끼를 포함했을 때 전체 범위 이탈과 주요 영양소 이탈이 모두 줄어드는 메뉴를 우선한다. 이 비교는 후보를 고르는 목업 로직이며 섭취량을 늘리라는 지시나 개인 건강 개선 효과를 예측한 결과가 아니다. 장보기 상품·닫힌 가게·잘못된 영양값은 후보에서 제외한다. 쿠폰은 영양 기준으로 선택한 뒤에만 적용 여부를 확인한다.
- 조리 경로에는 탄수화물 비중이 높은 경우 밥 반 공기·달걀·채소로 구성하는 예시를 제안하고, 레시피 본문의 밥 양도 함께 바꾼다. 단백질 비중만 낮은 경우 밥을 자동으로 줄이지 않는다. 레시피 전체 영양값은 미계산이며 완성 음식의 비율이 목표 범위가 된다고 표시하지 않는다.
- 화면 상단은 탄단지 비중을 먼저 보여준다. 상세 리포트의 쿠폰 후킹은 영양 분석 아래로 이동했다. 누락된 나트륨·당류·식이섬유는 추정해 채우지 않는다.
- 검증: JS 42개 통과. 참고 범위 경계, 균형 유지, 각 영양소 이탈 방향, 후보 영양값 비교, 미기록·0g·잘못된 데이터, 하루 기록, 기간 변경, 레시피 양 조정을 확인했다. 리포트와 빈 기간 HTML 출력·HTTP 제공 확인. 브라우저 비활성화로 화면 확인은 하지 못했다.

## 배민이지 PB 상품 제안

- 주문내역 요약·상세 리포트·장보기에서 배민이지 상품을 탐색하고 상품 상세·바로 담기·브랜드 필터로 연결한다.
- 2026-10-26 사용자 iPhone Mirroring에서 상품 사진·판매단위·표시 가격을 직접 확인했다: 갓 짜낸 1급A 우유 900mL 1,990원(정가 2,290원·13%), 순대많이 얼큰 순대국 700g 5,490원, 부산식 돼지수육국밥 700g 5,460원. 관찰 당시 매장/시점의 가격이며 실시간 연동이 아니다. 우유의 기존 `milk` ID와 이미 저장한 주문 가격은 보존한다.
- 실제 제품 영양성분표는 미확보하여 `nutrition:null`, `nutritionStatus:'not-provided'`로 둔다. 배민이지는 브랜드 탐색 영역이며 수치 기반 영양 균형 추천 후보에 포함하지 않는다. 장보기 배송 완료도 식사 합계를 자동으로 늘리지 않는다.
- 기존 두부는 제품명/단위 참고 자료와 생성 대표 사진을 유지한다. 1,980원은 목업 가격이다. [제품명 참고](https://www.ceoscoredaily.com/page/view/2026082013455095015).
- 기존 B마트 PB 보유 쿠폰은 새 배민이지 SKU도 인식한다. 최소금액·기한·사용 여부를 유지하며 실제 앱 쿠폰 발급은 수행하지 않는다.
- 캡처 원본은 웹 루트 밖에 보관한다. 상품 사진 3장만 공개 목록에 추가했다. [관찰 기록](qa/baemin-easy-mirror-observation.md), [이미지 출처](assets/README.md).
- 검증: JS 45개·Python 5개 통과. 구매/배송/저장 복원, 영양 미제공 상품의 식사 집계 제외, PB 쿠폰, 영양 추천 제외를 확인했다. 로컬 브라우저 비활성화로 이번 변경의 실제 화면/클릭은 미확인이다.
