# 식습관 리포트 → 다음 한 끼 → 보유 혜택

## 확인한 참고 자료

사용자가 지정한 [Figma 온라인 24페이지](https://www.figma.com/slides/xzk1SSi1Z6G8aJYM36F500/?node-id=231-1151)를 브라우저에서 직접 읽었다. ‘내 식사 기록을 한 눈에’, 주·월 리포트, 영양 정보와 날짜별 막대, 기록 이해를 통한 다음 식사 선택을 참고했다. Figma 연결 도구는 재인증이 필요해 브라우저 읽기로 대체했으며 슬라이드를 수정하지 않았다. 로컬 예전 발표본의 24쪽은 만보기여서 최신 온라인 24페이지와 구분했다.

## 제품 동작

1. 주문내역의 사진 캘린더 아래 요약 카드에서 식습관 리포트로 진입. 리포트에서도 주문내역 탭을 유지하며 상단 뒤로가기로 캘린더에 돌아온다.
2. 캘린더와 리포트가 월·주 선택을 공유한다. 월간은 선택한 달 1일~말일, 주간은 선택 날짜가 속한 일요일~토요일이다. 리포트에서 주·월/이전·다음을 바꿔도 캘린더가 같은 기간을 유지한다. 배달 식사 비중·평균 열량·메뉴 비중, 영양 합계와 일별 기록을 제공한다.
3. 배달/반복 메뉴 패턴이 있을 때 ‘직접 준비하기’와 ‘포케·샐러드’ 두 경로를 제안.
4. 집밥 재료는 B마트 PB/배민 장보기의 기존 상품 탐색·장바구니로 연결. 부족한 기본 재료는 집에 있는 재료로 명시. 실제 구매 단위 가격과 1인분 가격을 구별.
5. 포케·샐러드는 홈의 가게/메뉴 상세로 이동해 일반 담기/주문 경로를 사용.
6. 보유한 미확인 시연 쿠폰을 안내. 쿠폰을 ‘받기’로 새로 발급하지 않음. 쿠폰함을 열면 이미 있는 유효 쿠폰을 확인 상태로 전환.

## 지표와 추천 규칙

- 주문 집계: 주문 한국 날짜가 기간 안인 완료 음식 주문. 장보기·취소·진행 중 제외. 픽업은 따로 계산.
- 식사/영양: 먹은 날짜가 기간 안이고 확인해 저장한 기록만. 주문일과 섭취일이 달라도 각각의 기준을 유지. 연결된 장보기/취소/진행 중 주문은 식사에 합산하지 않음.
- 빈 날짜: 미기록. 0kcal 식사/결식으로 판정하지 않음. 평균 열량은 확인한 식사 수로 나눔.
- 배달 빈도 제안: 7일당 완료 배달 4회 이상으로 기간 길이에 비례한 기준을 적용하고, 3일 이상에 걸쳐 주문. 비슷한 메뉴 제안: 완료 배달 3회 이상 중 동일 가게 분류가 60% 이상. 이는 **탐색 유도용 목업 규칙**이며 건강/영양 불균형의 의학적 기준이 아님.
- 채소 메뉴 표시는 제공 메뉴 ID/구성에 따라 분류. 직접 기록 사진에서 채소 유무를 임의로 단정하지 않음.
- 나트륨·당류 미제공. 예시 영양값과 확인한 사진 분석값의 출처는 원본 식사 기록에 유지.

## 쿠폰 상태/결제

`state.coupons`: id, shopId, service, discount, minOrder, issuedAt, expiresAt, seenAt, usedAt, usedOrderId, 선택적 allowedMenuIds/requiredMenuIds, source.

| 시연 쿠폰 | 조건 |
| --- | --- |
| 포케·샐러드 2,000원 | 민트키친의 지정 메뉴, 10,000원 이상 |
| B마트 PB 3,000원 | PB 상품 포함, 9,000원 이상 |
| 동네마트 1,000원 | 지정 가게, 10,000원 이상 |

쿠폰 선택은 장바구니에 보존하며 주문 직전에 조건을 다시 검사한다. 한 주문에 한 장만 사용하고 대상 메뉴 금액보다 큰 할인은 적용하지 않는다. 주문 스냅샷과 쿠폰 사용은 동일 상태 변경에서 저장한다. 동일 시도 ID 재처리는 중복 사용하지 않으며 새로운 주문에서 재사용하면 거절한다. 접수 대기의 전체 취소는 할인 후 실지불액을 환불하고 쿠폰 기간은 늘리지 않는다.

실제 제품에서는 서버 발급 쿠폰/가격/상품/고객 자격을 검증하는 정식 제공 경로가 필요하다. 이 목업의 쿠폰·PB 상품·가격은 실제 계정 혜택이나 실제 B마트 PB 상품 정보가 아니다.

## 검증

- 자동 32개 통과: 기존 26개 + 사진 캘린더/날짜 혜택 6개. 빈 날/섭취일/장보기 분리, 최소금액/대상/유효기간/PB 조건, 사용·중복·취소 복원, 예시 표시의 원본 보존 확인.
- 브라우저: 주간/월간, 미확인 주문 표시, 배달 집중 예시, 집밥/포케 이동 확인.
- PB 재료 9,960원에서 보유 쿠폰 3,000원 적용 후 장바구니 6,960원 확인.
- 연어 포케 13,500원에서 보유 쿠폰 2,000원 적용 후 장바구니 11,500원 확인.
- 결제 확정/주문 생성은 추가하지 않음. 검증 전 기존 장바구니의 채소 비빔밥 1개/11,000원/쿠폰 미사용을 그대로 복원.
- 기존 미확인 쿠폰 안내를 남기기 위해 브라우저 검증에서는 쿠폰함 확인 상태를 변경하지 않음. 확인 전환/사용 처리는 자동 테스트로 검증.
- ‘민수’ 이름, 이름 옆 편집 아이콘 제거, 고객센터/설정 PNG 로딩 및 정사각형 배치 확인. 콘솔 오류 없음.

## 현황 요약 변경

기록 건수 중심의 상단 숫자를 식습관 현황으로 교체했다. 배달 식사 비중은 확인한 배달/픽업/직접 식사의 합계를 분모로 하며 연결 미확인은 제외한다. 한 끼 평균은 확인한 식사 열량 합계/식사 수다. 메뉴 비중은 기간 내 완료한 배달 주문의 가게 분류를 기준으로 한다. 탄단지 막대는 기록 g × 4/4/9의 에너지 구성비이며 개인 목표나 적정량을 뜻하지 않는다. 데이터가 없으면 비율/평균을 만들지 않는다. 추가한 2개 자동 검증으로 소스별 분모, 기간/완료 상태, 0·반올림 경계를 확인한다.

## 캘린더 기간 연동과 화면 안내 정리

- UI는 `state.month`, `state.selectedDate`, `state.view`를 단일 기간 선택으로 사용한다. `calendarReportWindow`가 달 전체/일요일 시작 주간을 만들고 `buildReport`에 명시적인 시작·종료일을 넘긴다. 기존 최근 7일 API는 호환성을 위해 유지하되 UI는 사용하지 않는다.
- 요약 카드에서 탄단지 막대·비율·설명을 제거했다. 영양 데이터 자체와 상세의 g값은 유지한다.
- 다음 한 끼 연결은 선택 기간의 식사 패턴과 추천 이유를 먼저 보여준다. 2일 이상·3끼 이상 기록에서 배달 비중 70% 이상이면 달걀 채소 볶음밥 레시피를 제안한다. 동일 메뉴가 2회 이상·완료 배달의 40% 이상이거나, 완료 배달 3건 이상·동일 분류 60% 이상이면 다른 메뉴를 제안한다. 메뉴마다 한 주문은 한 번만 집계하고, 취소·장보기·기간 밖 주문은 제외한다. 직접 기록 2끼 이상·배달 비중 70% 미만이면 15분 집밥을 제안하되 직접 기록을 자가 조리로 해석하지 않는다. 충분한 기록에서 알려진 메뉴 분류가 3개 이상이고 앞선 패턴이 없다면 다양한 선택의 관찰과 포케를 제안한다. 부족한 기록에는 식사 기록 진입을 제공한다. 임상적 건강 점수나 영양 균형의 좋고 나쁨을 단정하지 않는다.
- 보유 쿠폰은 추천 메뉴에 실제 적용 가능한 경우에만 보조 문구로 표시한다. 할인 금액을 대표 제목으로 사용하지 않는다.
- 빈 날짜는 숫자/단위 없이 첫 식사 등록 안내를 표시한다. 시연·실제 연결 여부 안내는 화면에서 제거했으며 내부 데이터 출처와 이 문서의 연동 한계는 보존한다. 음식 선택 등록을 AI 사진 분석으로 표시하지 않는다.

## 일별 식사 요약 강조

날짜 아래의 얇은 열량 띠를 큰 카드로 교체했다. 기록한 식사 수·총 열량·최대 3개의 음식 사진을 표시하며 카드를 누르면 해당 날짜의 음식별 기록이 열린다. 합계는 기존과 동일하게 확인한 식사만 사용하고 주문 완료 건수와 혼합하지 않는다.

최신 검증: JS 36개 + Python 5개 = 41개 통과. 별도 127.0.0.1 저장소에서 배달 비중 → 달걀 채소 볶음밥 레시피 이동과 일별 요약 → 음식 기록 팝업 이동을 확인했다.

고정된 수의 일반 추천을 채우지 않는다. ‘내 식사 기록’ → ‘추천 이유’ → ‘다음 한 끼’ 순서로 표시하며, 상세 리포트도 같은 `mealSuggestions` 결과의 목적지만 노출한다. 반복 메뉴에서 아직 주문하지 않은 메뉴를 우선 고르되 이미 주문한 메뉴를 새 메뉴라고 단정하지 않는다. 최신 JS 자동 검증 38개 통과. 화면 확인은 Work의 로컬 브라우저 비활성화로 미실시.

## 영양소와 균형 중심으로 추천 기준 교체

이전의 배달 비중·메뉴명·주재료 반복을 근거로 한 추천은 `mealSuggestions`에서 제거했다. 현재 기준은 확인한 식사에 저장된 탄수화물·단백질·지방 g을 4/4/9kcal로 환산한 에너지 구성이다. 표시·비교는 소수 첫째 자리까지 한다.

- 참고: 보건복지부·한국영양학회의 [2025 한국인 영양소 섭취기준](https://www.kns.or.kr/fileroom/fileroom_view.asp?BoardID=Kdr&idx=168), 일반 성인 탄수화물 50~65%, 단백질 10~20%, 지방 15~30%. 개인 연령·질환별 목표를 설정한 서비스가 아니며 선택 기간에 기록한 식사의 구성을 비교한다. 하루 필요열량·영양 결핍을 판정하지 않는다.
- 범위 안이면 탄단지 구성을 유지하는 방향으로 안내한다. 범위 밖이면 해당 영양소 비중과 일반 참고 범위를 보여주고, 주식·단백질 반찬·채소를 함께 구성하는 구체적인 방향을 안내한다. 영양정보가 없으면 메뉴명으로 영양 상태를 추정하지 않는다.
- 후보 메뉴의 카탈로그 영양값을 직접 비교한다. 후보 자체의 에너지 구성이 참고 범위 안에 있고, 기록 합계에 다음 한 끼를 포함했을 때 전체 범위 이탈과 주요 영양소 이탈이 모두 줄어드는 메뉴를 우선한다. 이 비교는 후보를 고르는 목업 로직이며 섭취량을 늘리라는 지시나 개인 건강 개선 효과를 예측한 결과가 아니다. 장보기 상품·닫힌 가게·잘못된 영양값은 후보에서 제외한다. 쿠폰은 영양 기준으로 선택한 뒤에만 적용 여부를 확인한다.
- 조리 경로에는 탄수화물 비중이 높은 경우 밥 반 공기·달걀·채소로 구성하는 예시를 제안하고, 레시피 본문의 밥 양도 함께 바꾼다. 단백질 비중만 낮은 경우 밥을 자동으로 줄이지 않는다. 레시피 전체 영양값은 미계산이며 완성 음식의 비율이 목표 범위가 된다고 표시하지 않는다.
- 화면 상단은 탄단지 비중을 먼저 보여준다. 상세 리포트의 쿠폰 후킹은 영양 분석 아래로 이동했다. 누락된 나트륨·당류·식이섬유는 추정해 채우지 않는다.
- 검증: JS 42개 통과. 참고 범위 경계, 균형 유지, 각 영양소 이탈 방향, 후보 영양값 비교, 미기록·0g·잘못된 데이터, 하루 기록, 기간 변경, 레시피 양 조정을 확인했다. 리포트와 빈 기간 HTML 출력·HTTP 제공 확인. 브라우저 비활성화로 화면 확인은 하지 못했다.
