# 카테고리·만보기 및 오류 수정

## 동작

- 홈 카테고리(치킨·피자·카페·디저트 등) → 전용 가게 목록 → 가게 → 메뉴 상세 → 장바구니 → 주문. 카테고리 가로 이동, 검색, 정렬, 영업 중/별점 필터, 찜, 배달·픽업 선택을 제공한다. 가게·메뉴는 기존 로컬 카탈로그이며 실제 배민 가게 검색 API는 아니다.
- 만보기 카드는 마이배민의 프로필 바로 아래로 옮겼다. 홈·주문내역에서는 제거했다. 첨부 카드의 어두운 배경/민트 보상 버튼/걸음·칼로리/픽업 부스터 구조를 Flutter로 구현했다.
- iOS Core Motion `CMPedometer.queryPedometerData`로 한국 시간 오늘 0시부터 현재까지 걸음 수를 읽는다. 사용자가 연결을 누르기 전에는 권한을 요청하지 않는다. 이미 허용된 경우 앱 복귀와 30초 간격으로 갱신한다. 건강 앱/Apple Watch 합산이나 HealthKit 연동은 포함하지 않았다.
- 웹에는 3,665걸음·120kcal·픽업 부스터 24P 예시를 표시하며 상세 화면에서 미리보기 값임을 구분한다. 웹에서 실제 걸음 수를 측정하지 않는다.
- 앱의 로컬 보상 규칙은 1,000걸음당 4P, 하루 10,000걸음까지다. 당일 음식 픽업 완료 시 X2로 최대 80P이며 이미 받은 금액을 차감한 차액만 지급한다. 실제 배민 포인트 발급과 연결하지 않았다.
- 소비 칼로리는 걸음 수 × 0.0327 kcal의 단순 참고값이다. 체중/속도에 따른 개인화·측정값으로 제시하지 않는다. 음식 섭취 열량에서 자동 차감하지 않는다.

## 수정한 오류

- 찜과 주문내역의 배달/장보기 선택 상태를 분리했다.
- 월간 이동 시 29~31일이 무조건 28일로 바뀌던 문제를 해당 월의 마지막 날짜까지 유지하도록 수정했다(윤년 포함).
- 쿠폰 대상 메뉴 삭제/최소금액 미달 시 유효하지 않은 선택 쿠폰을 해제한다. 만료된 쿠폰이 복원돼 있어도 이유와 명시적인 해제 버튼을 제공한다.
- 가게 장바구니 교체 요청의 수량을 먼저 검증해 실패해도 기존 장바구니/쿠폰이 지워지지 않는다.
- 주문 확정 전에는 장바구니로 돌아가 수정할 수 있고, 확정 후 뒤로가면 비어 있는 장바구니가 다시 열리지 않는다.
- 픽업 주문은 수령 가게/가게 요청사항/기본 요청사항을 표시한다. 픽업 준비 완료·상품 준비 중·배송 중을 배달 상태와 구분한다.

## 검증

- Flutter 테스트 62개 통과. 신규 회귀 8개, 카테고리·만보기·라이브 액티비티 11개 포함. 360/393/430px 주요 탭과 만보기 렌더, 카테고리→가게 이동, 필터/검색/정렬, 보상 중복/상한/보관/날짜 변경, 픽업 조건, 권한 요청 여부를 확인했다.
- Dart analyzer 진단 없음. 웹 release 빌드 성공. iOS release 빌드 번호 5(약 40.5MB) 서명 검증·기존 iPhone 14 Pro에 덮어 설치 성공.
- 기존 웹 97개 파일 SHA-256이 기준과 동일하다. 4180/사진 분석 공급자는 변경하지 않았다.
- 설치 직후에는 iPhone 잠금으로 실행이 차단됐다. 이후 미러링 재연결 후 실제 아이폰 홈의 만보기 카드와 치킨 카테고리 → 가게 목록 화면 전환을 확인했다. 사용자가 운동 및 피트니스 권한을 허용한 뒤, 실제 걸음 수와 참고 칼로리·보상이 앱에 표시되는 것을 미러링에서 확인했다. iOS 설정의 실시간 현황 허용을 확인하고 앱 안의 표시 스위치를 켠 뒤, 앱 밖의 다이내믹 아일랜드를 길게 눌러 실제 걸음 수·칼로리·포인트 표시를 확인했다. ‘걸음 확인’ 링크를 눌러 만보기 상세로 돌아가는 동작도 직접 확인했다. 잠금화면 카드 자체는 미러링에서 확인하지 못했다. 브라우저 자동 조작은 Work 설정에서 비활성화되어 최종 웹 클릭 검증 대신 Flutter 위젯 상호작용·렌더를 사용했다.
- `category-chicken.png`, `walking-card.png`, `walking-detail.png`은 Flutter 위젯 테스트 캡처이며 실제 iPhone 측정 화면이 아니다.

공식 API: https://developer.apple.com/documentation/coremotion/cmpedometer

## 잠금화면 표시

- ActivityKit + SwiftUI/WidgetKit 앱 확장 `WalkingActivity.appex`를 추가했다. 같은 개인 Team으로 서명하고 Runner에 포함해 기기에 설치했다. 푸시 서버/알림 권한/APNs는 사용하지 않는다.
- 만보기 상세의 ‘잠금화면에 걸음 수 표시’로 시작/종료한다. 현재 걸음 수·소비 칼로리 참고값·받을 보상·픽업 부스터를 표시한다. 라이브 액티비티의 보상 링크는 `hankki://walking`으로 마이배민 만보기를 연다. 실제 보상 수령은 앱에서 진행한다.
- 앱이 실행되는 동안 동기화하며, 2분 이상 갱신되지 않은 값은 ‘앱에서 최신 걸음 확인’으로 구분한다. 지속 백그라운드 걸음 갱신이나 무기한 고정 알림을 보장하지 않는다. iOS에서 활동 상태는 최대 8시간, 종료 후 잠금화면 잔류는 추가 최대 4시간이다.
- 사용자가 지웠거나 시스템이 종료한 활동은 자동 재생성하지 않는다. 앱에서 다시 켤 수 있다.
- Flutter 테스트에서 시작/갱신/종료 계약·오늘의 걸음/보상 값·수동 종료 존중·딥링크 전달을 검증했다. 원본 웹은 변경하지 않았다.
- `iphone-walking-live-island.jpg`는 실제 iPhone 미러링에서 확인한 다이내믹 아일랜드 펼침 화면이다.

공식 Live Activities 문서: https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities
