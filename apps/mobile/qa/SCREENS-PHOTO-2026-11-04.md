# 화면 분리·사진 분석 후속

## 구현

- 기존 약 2,050줄의 HomeShell을 탭 이동·장보기 진입·만보기 수명 관리로 축소했다. 홈/장보기/찜/주문내역/마이배민을 각각 독립 상태 화면으로 옮겼다.
- 캘린더와 직접 음식 기록 카드를 주문내역에서 분리했다. 홈/장보기 상품 그리드·가게 행·브랜드 아이콘을 재사용한다. 공통 화면 틀은 기능 모듈을 가져오지 않고 콜백으로 이동한다.
- 사진 등록 화면과 요청/기록 컨트롤러를 분리했다. 실제 파일의 시그니처와 5MB 제한을 확인하고 전송 동의를 받아 모델을 호출한다.
- 사진 교체 시 이전 음식명·영양값·동의를 초기화한다. 교체/화면 종료 후 도착한 응답을 무시한다. 분석 중 중복 호출/저장은 막는다.
- 분석 성공 후 재료·음식명·전체 추정 열량을 보여 주고 먹은 양 25/50/75/100%를 선택한다. 수동 수정 후에는 섭취량 선택이 수정값을 덮어쓰지 않는다.
- 원본 전체 영양값·모델 ID·섭취 비율·수정 여부를 분석 메타데이터로 저장한다. 재실행/가져오기 후에도 남고 캘린더 카드에서 다시 확인할 수 있다.
- 빠른 음식 입력은 모바일 카탈로그에서 기준값을 읽는다. 비빔밥 707kcal/국수 599kcal/연어 샐러드 포케 450kcal로 서버 예시 입력도 맞췄다. 실제 모델 분석값으로 위장하지 않는다.
- 서버는 크레딧/인증/접근 권한/요청 한도/타임아웃/잘못된 응답을 코드로 구분한다. 앱은 크레딧 오류를 직접 입력 경로와 함께 보여준다. JSON 객체가 아닌 응답도 읽을 수 있는 오류로 처리한다.

## 실제 Hugging Face 확인

- 사용자가 Hugging Face 유지를 선택했다. 다른 공급자나 가짜 성공 결과를 추가하지 않았다.
- 공개 모델 메타데이터에서 `Qwen/Qwen2.5-VL-7B-Instruct`의 featherless-ai conversational 제공 경로를 확인했다.
- 앱에 있는 범용 버거 이미지 1장을 기존 토큰/모델로 실제 전송했다. 약 1.5초 후 추론 크레딧·결제 한도 오류가 반환됐다. 토큰은 출력하거나 커밋하지 않았다.
- 따라서 현재 코드의 성공 흐름은 통제된 모델 응답으로 검증했으며, 실제 외부 모델의 음식 식별·칼로리 정확도나 실기기 카메라→성공 응답은 아직 검증하지 못했다. 계정 크레딧이 준비돼야 실제 성공 검증을 마무리할 수 있다.
- 공식 호출 계약: https://huggingface.co/docs/inference-providers/tasks/image-text-to-text

## 검증

- Flutter 테스트 80개 통과. 기존 다섯 탭·가상 주문·쿠폰·리포트 동작과 탭별 필터 보존/장보기 진입 초기화를 확인했다.
- 사진 분석 응답 후 50% 선택 → 400kcal 저장 → 원본 800kcal/모델/수정 여부 보존 → 저장 상태 재조회까지 통제된 응답으로 검증했다. 이미지 교체 중 늦은 응답, 화면 종료 후 응답, 동의 전 차단, 한도 오류, 중복 저장 방지도 확인했다.
- 웹 테스트 46개, Python 분석/API 테스트 13개 통과. Dart 정적 분석 오류 없음.
- Flutter 웹 release 및 서명된 iOS 빌드 11(52.7MB) 성공. 웹 4181과 API 4182 설정 조회 HTTP 200 확인. API는 현재 Mac LAN 주소에 바인딩했다. 토큰 설정 상태는 실제 모델 이용 가능 상태와 구분한다.
- `qa/photo-analysis-review.png`는 통제된 응답을 넣은 로컬 위젯 렌더 캡처다. 실기기 촬영·모델 성공 결과가 아니다.
- iPhone 설치 시 개발자 디스크 이미지 마운트가 기기 잠금 오류로 중단됐다. 사용자가 설치를 나중에 진행하기로 선택해 추가 설치 시도는 하지 않았다.
