# 영양 추정값·몽촌 닭갈비 추가

## 범위와 기준

- 원본 4180 웹 파일은 수정하지 않고 Flutter의 번들 카탈로그를 변경했다.
- 기존 31개 메뉴/식재료의 칼로리·탄단지·제공량을 보정했다. 배달 메뉴의 열량은 ‘주문 1개 전체’ 기준이다. 치킨 한 마리, 피자 한 판, 2개 세트와 개인 섭취량을 구분한다.
- 비빔밥은 식약처 자료집의 500g 707kcal, 비빔국수는 550g 618kcal, 잔치국수는 700g 599kcal를 일반 음식 참고값으로 사용했다. 김치찌개·된장찌개는 자료집의 찌개 400g에 공깃밥 210g 310kcal를 더했다. 떡볶이는 200g 참고값을 300g으로 환산했다.
- 포케·두부 덮밥·피자·치킨·버거 등 조리법이 정해지지 않은 메뉴는 일반 재료 구성과 가정한 분량을 기준으로 칼로리와 탄단지 4/4/9 환산이 일치하도록 보정한 추정값이다. 특정 매장 측정값이 아니다.
- 영양표시를 확인하지 못한 배민이지 우유·순대국·돼지국밥·두부는 `nutrition:null`을 유지했다. 확인하지 못한 수치를 새로 만들지 않았다.
- 단일 메뉴를 여러 명이 나눠 먹는 주문은 1명 몫을 기본 선택한다. 예: 닭갈비 2인분 1,200kcal 주문 → 기본 50% 600kcal. 먹은 비율은 10·25·50·75·100% 및 해당 기본 분율 중 변경한다. 주문 전체의 100%를 초과해 기록하지 않는다.

## 몽촌 닭갈비

- 네이버 원문은 ‘서비스 이용 제한’으로 열리지 않았다. 이를 우회하지 않고 같은 이름/잠실 주소의 다이닝코드 공개 메뉴를 확인했다.
- 주소: 서울 송파구 석촌호수로 298, 104·105호.
- 추가 메뉴: 몽촌 한방 닭갈비 17,000원, 몽촌 매콤 닭갈비 17,000원, 포장 2인분 30,000원, 들기름 비빔 칼국수/옛날 냉 칼국수 각 9,500원. 가격은 공개 목록 참고값이며 네이버 현재값을 직접 확인한 것은 아니다.
- 기본 닭갈비는 수량 2로 진입한다. 가상 주문은 최소 닭갈비 2인분과 최소금액 30,000원 조건을 적용한다. 배민 입점·실제 배달 가능·실시간 영업 상태를 확인했다는 의미가 아니다. 별점·예상 배달 시간을 만들지 않았다.
- 한방 400g 약 600kcal, 매콤 400g 약 620kcal, 포장 800g 약 1,200kcal로 가정했다. 식약처 I2790의 일반 닭갈비 400g 595.61kcal(C44.9/P45.9/F25.8) 참고값을 반올림·양념 차이를 가정한 값이다. 칼국수는 구성에 따른 별도 추정이다. 메뉴 화면에 ‘일반 음식 기준 추정값’과 기준량을 표시한다.
- 공개 메뉴 사진 2개를 `assets/food/mongchon-{herbal,spicy}.webp`에 저장했다. 각 사진은 다이닝코드 메뉴에 연결된 이미지이며 전체 사진을 왜곡하지 않고 BoxFit.cover로 표시한다.

## 저장·갱신

- `assets/seed.json`은 앱 내장 데이터다. 수정 시 웹은 빌드·새로고침, 설치된 iOS 앱은 재빌드·재설치가 필요하다. 서버 원격 카탈로그 기능은 이번 범위에 추가하지 않았다.
- `data/catalog-updates.json`에 추가 메뉴·보정값·이전값·출처를 보관한다. `tools/export_web_seed.mjs`도 이 파일을 병합해 원본 웹에서 다시 추출하더라도 이번 수정을 유지한다.
- 기존 주문 스냅샷이 알려진 이전 기본값과 일치할 때만 영양값/분량 메타데이터를 변경한다. 해당 주문에 연결된 배민 가상 식사 기록도 이전 총량×먹은 비율과 일치할 때만 재계산한다. 날짜·수량·결제금액·리뷰·사진/수동 수정 영양값은 유지한다. 버전과 영양값 일치 조건으로 중복 보정을 방지한다.

## 검증

- Flutter 테스트 67개 통과. 메뉴별 기준량·칼로리와 탄단지의 일관성, 알려진 이전 기본값만 보정하는 마이그레이션, 사진/수정값/결제금액 보존, 보정 중복 방지, 닭갈비 최소 2인분 주문을 확인했다.
- 위젯에서 몽촌 가게 → 한방 메뉴 기본 수량 2 → 34,000원 담기 → 주문 완료 → 기본 50% 600kcal 식사 기록까지 확인했다. `qa/mongchon-shop.png`는 위젯 렌더 캡처다.
- 원본 웹 97개 파일 SHA-256 동일. iOS 빌드 9와 웹 release 빌드를 준비했다. 현재 iPhone은 unavailable 상태이므로 빌드 9의 실기기 설치·동작 검증은 대기 중이다.

## 패스트푸드 브랜드 추가

- 맥도날드(빅맥·상하이·빅맥 세트), 버거킹(와퍼·치즈와퍼·와퍼 세트), 롯데리아(리아불고기·리아새우·리아불고기 세트), 맘스터치(싸이·화이트갈릭·싸이 세트), KFC(징거·타워·징거 세트)를 추가했다. 기존 버거룸은 유지했다.
- 패스트푸드 목록에서 브랜드 버튼으로 바로 필터링하고, 가게 → 메뉴 → 장바구니 → 주문 흐름을 그대로 사용한다. 홈 대표 가게 순서는 유지한다.
- 단품은 버거 1개 전체, 세트는 버거·중간 감자튀김·일반 콜라 355mL 전체로 구분했다. 15개 메뉴의 영양값은 일반적인 구성·분량을 가정한 추정값이며 공식 제품별 영양성분이 아니다. 가격도 가상 주문용 참고 가격이다. 임의 지점명·별점·배달시간은 넣지 않았다. 최소주문 조건 미확인 값은 목록에 0원으로 노출하지 않는다.
- 사진은 기존 범용 버거 이미지를 사용한다. 실제 브랜드 제품 사진으로 검증한 것이 아니다. 카탈로그에 출처 종류를 남겼다.
- 브랜드/메뉴 참고: [맥도날드](https://www.mcdonalds.co.kr/kor/menu/burger), [버거킹](https://web-prd.burgerking.co.kr/menu/main), [롯데리아](https://img.lotteeatz.com/shopping/main), [맘스터치](https://momstouch.co.kr/), [KFC](https://www.kfckorea.com/kfc/index.asp). 각 공식 사이트의 모든 현재 판매·가격·영양 정보를 확인한 것은 아니다.
- 전체 테스트 69개 통과, Dart 분석 오류 없음. 360px 브랜드 필터 → 버거킹 가게 → 와퍼 세트 상세 → 9,900원 담기 → 전체 1,100kcal 주문 스냅샷 생성 검증. `category-fastfood.png`는 위젯 렌더 캡처다. 공식 앱 실측 화면이 아니다.
- Flutter 웹 release 업데이트 및 4181에서 5개 브랜드/15개 메뉴가 제공됨을 확인했다. 원본 웹 97개 파일 해시 동일.
- iOS release 빌드 10(52.6MB) 생성 및 서명 검증 성공. iPhone 연결이 unavailable이어서 설치는 대기 중이다. 실제 새 버전 실행을 확인한 것은 아니다.
- 이후 iPhone 14 Pro 연결 복구 후 빌드 10 앱 설치 및 프로세스 실행 명령 성공을 확인했다. 해당 버전의 실기기 화면별 동작은 아직 직접 관찰하지 않았다.
