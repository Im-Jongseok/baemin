## 검증

- `dart analyze --format=machine`: 진단 없음.
- Flutter 테스트 40개: 기존 주문·쿠폰·사진 API 계약에 더해 캘린더 미확인/취소/장보기 구분, 재주문 원자성, 요청사항 저장, 상세 화면 탭 이동/기록 조회, 혜택 → 장보기 이동, 리포트 앵커/레시피 펼치기, 홈 → 가게 → 메뉴 이동 확인.
- 다섯 하단 탭을 360/393/430px에서 렌더하고 overflow 예외를 확인했다.
- 실제 4181 release 화면에서 홈·장보기·주문내역·주문 상세를 확인했다. `parity-flutter-*.jpg`는 실제 브라우저 캡처다. `parity-order-widget.png`는 360px 테스트 렌더다.
- 원본 웹 97개 파일의 SHA-256이 기준 스냅샷과 동일하다. 기존 웹의 브라우저 저장 데이터는 가져오거나 덮어쓰지 않았다.

## 비교 시 주의

원본 4180의 현재 브라우저에는 사용자가 추가한 주문과 식사 기록이 있다. Flutter는 별도 로컬 저장소의 seed/기록을 사용하므로 주문 개수·칼로리는 다를 수 있다. 이를 화면 차이로 취급해 임의로 덮어쓰지 않았다.

픽셀 단위 동일성, 실제 배민 API/결제/쿠폰 발급, HF 모델의 실제 추론 성공, iPhone 실기기 빌드·카메라 권한·미러링은 이번 비교 검증 범위가 아니다. iOS 빌드에는 전체 Xcode/서명 설정이 여전히 필요하다. 배민이지 국밥의 미확인 영양성분은 계속 null로 유지했다.
