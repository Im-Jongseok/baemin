# HF 사진 분석 경로 확인

- 기존 경로: `Qwen/Qwen2.5-VL-7B-Instruct:featherless-ai`.
- Hub 메타데이터의 live 상태와 달리 라우터 제공 모델 목록에는 없었고, 실제 POST는 HTTP 400 `model_not_deployed`를 반환했다. 결제 오류와 별개다.
- 현재 경로: `Qwen/Qwen3-VL-30B-A3B-Instruct:deepinfra`. HF 라우터의 `/v1/models` 응답에서 image 입력, live 제공 상태를 확인했다. HF 토큰·라우터 결제를 유지한다.
- 기존 앱의 `assets/food/burger.png` 한 장으로 실제 분석 함수 호출 성공: HTTP 200, 4.2초, 입력 213/출력 89/총 302토큰, 종료 사유 stop. 최대 출력은 256토큰으로 제한했다.
- 결과: 햄버거, 650kcal, 탄수화물 55g/단백질 30g/지방 35g. 추정값이며 영양 정확도 평가 결과가 아니다.
- 응답의 estimated_cost: **$0.00008535**. 확정 청구액·잔여 크레딧은 확인하지 않았다.
- 이번 점검의 추론 POST는 두 번(기존 경로 오류 확인 1회, 새 경로 성공 1회)이며 자동 재시도는 없었다. 모델 목록 GET은 추론 요청과 별도로 조회했다. 추가 유료 호출을 하지 않았다.
- 서버 기본값·로컬 .env·실행 예제를 갱신했다. 토큰과 사진 본문·공급자 오류 원문은 저장소에 포함하지 않는다.
- 진단 CLI는 기본 출력 한도 256 및 오류 HTTP 상태를 표시한다. 앱에는 공급자 원문 없이 모델 경로/결제/인증 오류를 구분해 전달한다.
- Python 분석/API 테스트 14개 통과. 제한 토큰 전달·단일 호출·400/404 상태 분류를 통제된 응답으로 검증했다. 실기기 카메라→저장은 이번에 실행하지 않았다.

참고: [HF 이미지 입력 API](https://huggingface.co/docs/inference-providers/tasks/image-text-to-text), [HF 라우터 제공 모델 목록](https://router.huggingface.co/v1/models).
