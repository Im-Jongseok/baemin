# 만보기 갱신·디자인 보완 (2026-10-29)

## 변경

- `CMPedometer.startUpdates(from:withHandler:)`의 오늘 누적 걸음 이벤트를 EventChannel로 Flutter에 전달한다. 기존 30초 조회는 복귀·연결 실패 시의 보완 수단으로 남겼다. 권한 미결정 상태에서 자동 스트림 연결만으로 권한 창을 띄우지 않는다.
- 걸음 이벤트를 받으면 화면·참고 칼로리·받을 보상을 갱신한다. 이전 시점의 조회 응답은 최신 걸음 이벤트를 덮어쓰지 않는다. 구독 해제 시 네이티브 측정도 정지한다.
- 백그라운드 실행이 허용되는 동안 수신된 네이티브 걸음 이벤트는 Live Activity에도 반영한다. iOS가 앱을 suspended 상태로 전환하면 이벤트 전달은 중단되므로, 잠금 중 매 걸음 즉시 갱신은 보장하지 않는다. 앱 복귀 시 오늘 누적 걸음을 다시 불러온다.
- 보상을 받은 직후 Live Activity에 수령한 포인트를 반영한다. 하루 보상·픽업 부스터 계산 방식은 유지했다.

## 디자인 출처

- 사용자 링크의 `304:205`는 멤버십 비교 슬라이드다. 같은 덱에서 만보기 슬라이드 `231:1291`, 알림 카드 `250:72`를 찾았다. Slides는 `get_design_context`를 지원하지 않아 읽기 전용 Plugin API의 레이어·색·크기·텍스트 정보를 확인했다.
- 카드: 기준 367×102, 모서리 16, 로고 50×48, 우측 보상 88×86/모서리 14, 버튼 64×28/모서리 8. 짙은 청록 배경·민트 강조·흰 걸음 수를 앱 카드와 잠금화면 카드에 적용했다.
- `508:4031` 로고 레이어를 PNG 4배(200×192)로 내보냈다. `assets/captured/walking-logo.png` 및 확장 Asset Catalog의 `WalkingLogo`에서 사용한다. 화면 전체 이미지를 배경으로 사용하지 않았다.
- 잠금화면 확장도 기존 프로젝트의 Noto Sans KR 가변 글꼴을 공유한다.
- 마이배민 배치, 권한 연결, 보상 수령, 목표와 픽업 연결, 잠금화면 설정은 유지한다.

## 검증과 남은 확인

- Flutter 테스트 63개 통과. 360/393/430px 카드 렌더·로고 실제 디코딩·보상 수령·상세 진입을 확인했다. 이벤트 수신 즉시 숫자가 바뀌고, 뒤늦은 과거 조회가 이를 되돌리지 않는 회귀 검증을 추가했다.
- Dart analyzer 진단 없음. 웹 release 및 iOS release 빌드 번호 6(51.0MB) 성공. 코드 서명 검증 통과. 확장 로고 Asset Catalog가 번들에 포함된다.
- 원본 웹 97개 파일은 기존 SHA-256과 동일하다.
- 후속 수정이 포함된 빌드 8(52.5MB)을 연결된 iPhone 14 Pro에 설치하고 실행에 성공했다. 실제 보행 중 자동 증가와 잠금화면 새 디자인의 실기기 확인은 아직 완료하지 않았다. `qa/walking-card.png`는 3,665걸음·부스터를 넣은 Flutter 렌더 미리보기이며 실기기 센서 검증 화면이 아니다.

공식 동작 기준: https://developer.apple.com/documentation/coremotion/cmpedometer/startupdates(from:withhandler:)

## 배경 후속 조정

- 앱 만보기 카드는 짙은 회청색 반투명 그라데이션, 배경 흐림, 얇은 유리 테두리, 약한 그림자로 수정했다. 보상 영역도 투명한 반사면으로 맞췄다. 로고·텍스트·버튼·배치·보상 계산은 유지한다.
- 잠금화면 카드도 SwiftUI ultraThinMaterial과 같은 계열의 반사 그라데이션을 적용했다. iOS 시스템 Liquid Glass API 자체를 사용한 화면이라고 주장하지 않는다.
- 카드/상세/카테고리 테스트 12개 통과, Dart analyzer 진단 없음. iOS 빌드 번호는 7이다. 후속 포인트 아이콘 교체까지 포함한 빌드 8을 실기기에 설치하고 실행했다.
